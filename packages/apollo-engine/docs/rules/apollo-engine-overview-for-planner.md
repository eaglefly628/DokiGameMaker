## 一、一句话理解 ZeroCraft

**ZeroCraft 是一个"乐高式"2D 游戏引擎。**

传统引擎：程序员写代码 → 编译 → 游戏
ZeroCraft：策划描述玩法 → AI 拼积木 → 游戏

引擎把所有游戏拆成 **26 块积木**（我们叫它"原子"），任何 2D 游戏都是这些积木的排列组合。

## 二、26 块积木一览

把它想象成一个玩具箱，里面装了 26 种零件：

### 位置与运动（让东西动起来）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| Transform | 放在哪里 | 设定角色/道具的初始坐标 |
| Velocity | 速度 | 角色移动速度、子弹飞行速度 |
| Acceleration | 加速度 | 重力、助推器、滑冰加速 |
| Mass | 质量 | 重物推不动、轻物被弹飞 |
| Hierarchy | 父子关系 | 武器跟着手、乘客跟着车 |

### 形状与碰撞（让东西碰到一起）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| Shape | 碰撞体 | 方形/圆形的碰撞区域 |
| Overlap | 碰撞检测 | "子弹碰到敌人 → 扣血" |
| Bounds | 边界 | 玩家不能走出屏幕 |
| Grounded | 站在地上 | 只有落地才能跳 |

### 外观（让东西看得见）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| Sprite | 图片 | 贴人物/场景的图片 |
| Color | 颜色 | 纯色方块、特效着色 |
| Frame | 帧动画 | 走路动画、攻击动画 |
| Text | 文字 | 伤害数字、对话文本 |
| Camera | 镜头 | 跟随主角、缩放战场 |
| Visibility | 显隐 | 隐藏陷阱、出场动画 |
| Sound | 音效 | 跳跃音效、BGM |

### 输入（让玩家操控）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| RawInput | 原始按键 | 读取键盘/触屏/手柄 |
| ActionMap | 操作映射 | "空格键 = 跳跃"、"左摇杆 = 移动" |
| Controllable | 可操控 | 标记哪个角色是玩家控制的 |

### 逻辑与数值（让游戏有规则）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| Resource | 数值 | 血量 100/100、MP 50/80 |
| Flag | 开关 | 宝箱已开、Boss 已击败 |
| State | 状态机 | 待机→攻击→受伤→死亡 |
| Tag | 标签 | "敌人"、"友军"、"可拾取" |
| Relation | 关系 | "A 的主人是 B"、"这把剑属于玩家" |
| Timer | 定时器 | 3 秒后爆炸、每 5 秒刷怪 |

### 生命周期（让东西出现和消失）

| 积木 | 作用 | 策划怎么用 |
|------|------|-----------|
| Spawn | 生成 | 按下按钮 → 发射子弹 |
| Destroy | 销毁 | 血量归零 → 角色消失 |

## 三、四层涌现模型

26 块积木按**从简单到复杂**堆成四层：

```
┌─────────────────────────────────────────────┐
│  第 4 层：行为层                              │
│  AI 巡逻、对话系统、视觉小说、养成系统         │
│  → 让游戏"有灵魂"                             │
├─────────────────────────────────────────────┤
│  第 3 层：机制层                              │
│  跳跃、射击、拾取、伤害、击退、弹射             │
│  → 让游戏"好玩"                               │
├─────────────────────────────────────────────┤
│  第 2 层：物理层                              │
│  碰撞分离、重力、摩擦力、边界约束               │
│  → 让游戏"像真的"                             │
├─────────────────────────────────────────────┤
│  第 1 层：运动层                              │
│  位移、加速、旋转、动画、计时                   │
│  → 让东西"能动"                               │
└─────────────────────────────────────────────┘
```

**策划只需要想清楚：这个玩法需要哪几层？**

- 弹幕射击 → 1+2+3 层
- 视觉小说 → 1+4 层
- 双人成行 → 1+2+3+4 全要

## 四、策划怎么描述一个游戏？

你不需要写代码。你只需要回答三个问题：

### 问题 1：场上有什么？（实体列表）

> "一个玩家角色、一片地面、三个平台、两个金币"

### 问题 2：它们有什么特性？（给实体贴积木）

> - 玩家：有位置、有速度、有碰撞体、可操控、有血量
> - 地面：有位置、有碰撞体、不可移动（质量=0）
> - 金币：有位置、有碰撞体、可拾取（标签=collectible）

### 问题 3：碰到会怎样？（交互规则）

> - 玩家碰到金币 → 金币消失 + 分数+1
> - 玩家碰到地面 → 停下来（碰撞分离）
> - 玩家离开屏幕 → 被边界弹回

**这就够了。** AI 会把你的描述翻译成引擎能读的 JSON 蓝图，引擎直接运行。

## 五、"一句话生成游戏"

这是 ZeroCraft 的核心卖点。流程如下：

```
策划："做一个双人抢金币的对战游戏，有重力"
  ↓
AI 理解需求，从 26 块积木里选出需要的：
  Transform + Velocity + Acceleration（重力）
  + Shape + Overlap（碰撞）
  + Controllable × 2（双人）
  + Resource（金币计分）
  + Spawn/Destroy（金币刷新/消失）
  + Camera（镜头）
  ↓
输出游戏蓝图（JSON 数据）
  ↓
引擎加载 → 直接可以玩
```

**支持的 AI 模型：**

| 模型 | 适用场景 |
|------|---------|
| Claude (Anthropic) | 最高质量，复杂游戏 |
| 通义千问 (Qwen) | 国内可用，中文理解好 |
| DeepSeek | 性价比高 |
| GPT-4o (OpenAI) | 通用能力强 |
| Ollama (本地) | 零成本，无需联网 |

不依赖任何一家 AI 供应商。同时内置预设模板，**不联网也能用**。

## 十、常见问题

**Q：这个引擎能做 3D 游戏吗？**
A：目前只支持 2D。但架构上预留了升级路径，渲染层可以替换。

**Q：能做手机游戏吗？**
A：可以。引擎跑在浏览器里，手机浏览器直接能玩。触屏输入已经在架构中预留。

**Q：AI 生成的游戏质量怎么样？**
A：取决于两件事——(1) 你描述得多清楚 (2) 用的 AI 模型多强。Claude/GPT-4o 能做出有趣的游戏，千问/DeepSeek 能做出能玩的游戏，本地小模型能做出基础原型。

**Q：我不懂编程，能参与开发吗？**
A：可以。策划的核心价值是"定义好玩"，这不需要编程。你负责决定场上有什么、规则是什么、关卡怎么排。AI 和程序员负责把它变成现实。

**Q：和 Unity/Unreal 比有什么优势？**
A：ZeroCraft 不是要替代它们。ZeroCraft 的独特优势是**AI 原生** —— 从第一天就为 "AI 自动组装游戏" 设计。传统引擎要实现这个需要大量适配，ZeroCraft 天然支持。
