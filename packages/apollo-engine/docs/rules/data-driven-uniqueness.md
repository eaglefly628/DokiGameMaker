# 为什么"用数据组织游戏驱动"是一种设计独特性
### ZeroCraft 技术原理白皮书（设计独特性 · Design Uniqueness）

> 归档于 `docs/design/`。与《数据驱动第一性原则》(`data-driven-manifesto.md`) 配套：宪法讲"必须这样"，本文讲"**为什么这样独特、独特在设计层而非实现层**"。
> 统一命名：**范式 = 「游戏即数据 Game-as-Data」；引擎 = 「确定性数据解释器 Deterministic Data Interpreter」；生成法 = 「约束式数据合成 Constrained Data Synthesis」。**

---

## 0. 一句话

> **整个游戏是数据；代码只是一台固定的、确定性的解释器。**
> 我们不是"写了一台更快的引擎"，而是做了一个**设计上的分叉**：把游戏的全部内容压成**闭集词汇上的数据**，由一台**确定性解释器**运行。这一个设计选择，**连锁**出后面所有的优势。

## 1. 关键区分：设计独特性 ≠ 实现独特性

- **实现独特性**（别人能追平）：ECS 跑得快、渲染好看、工具顺手——这些是"功能"，谁都能堆。
- **设计独特性**（别人难以retrofit）：**"整个游戏 = 闭集词汇上的数据 + 确定性解释器 + 引擎自描述这套词汇"**。这是**地基处的一个分叉决定**，它不是一个 feature，而是一组**不变量**——一旦在地基选定，上层所有红利**自动涌现**；而传统引擎/代码生成器在地基选了别的路，**事后补不回来**。

> 本文证明的就是这第二点：**我们的优势是一个设计决定的连锁后果，不是一堆功能的叠加。**

## 2. 三块地基（设计层的三个不变量）

### 地基 A · 闭集词汇 + 确定性解释器（Closed Vocabulary + Interpreter）
- **代码 = 引擎 + capability**：固定、审计过、确定性、**极少新增**——这是"动词/词汇表"。
- **数据 = 整个游戏**：实体 + 组件 + 能力接线 + 资产引用 + 内容——流动、可 diff、可回滚、**无限多**。
- "代码 vs 数据"的那条线**由架构强制**（闭集 ComponentDataMap + 能力注册表 + manifest 校验），不是靠自觉。

### 地基 B · 确定性（Determinism）——真正的拱心石
- 种子化 PRNG（mulberry32）、**canonical 哈希**（FNV-1a，排序后整数化）、**快照/回放**、lockstep、整数稳定。
- **为什么它是拱心石**：它让数据底座**可复现、可审计、可模拟、lockstep 安全**。后面每一项红利（生成可复现、AI 玩家自对弈、弱模型一致）**都压在这块石头上**。
- 传统引擎**没有把确定性当一等不变量**——这正是我们能做、他们难做的根因。

### 地基 C · 引擎自描述（Self-Describing）
- 每个 capability 自带 `describe{summary, whenToUse, examples, semantic}` + 组件 schema（`provides/reads/writes`）。
- **引擎能把"自己有哪些词汇"派生成数据**（`buildCapabilityCatalog`/`deriveAssetIndex`）。这把"让 AI 理解引擎"从"读源码/微调"降维成"**读引擎自己吐的结构化目录**"。

## 3. 连锁红利：一个设计选择 → 全部优势（这是论证的核心）

因为"游戏=确定性数据 + 自描述闭集词汇"，下面这些**不是各自做的功能，是同一个设计的必然后果**：

| 红利 | 它为什么"自动"来自地基 |
|---|---|
| **质量下限 · 不产生垃圾** | 数据只能引用闭集内的词汇 + 加载期校验 → **构造即可运行**，越界当场拒（地基 A+校验） |
| **可复现 / 每次一样** | 同数据 + 同解释器 = 同游戏，逐字节（地基 B） |
| **约束式数据合成（AI 造游戏）** | 引擎自描述目录注入模型 → 模型**只填数据不写代码** → 产出可运行、可复现、可审计（地基 C+A+B）→ **专利①** |
| **强弱模型可调和一致** | 任务被压成"在闭集里填表" → 方差暴跌；再按模型出错方差**自适应调约束** → **专利②** |
| **派生式分层知识索引** | 索引从自描述**派生**（非解析源码）、**确定性符号检索**（非向量库）、索引的是**数据样例**（非函数签名）→ 见 §5 |
| **美术 / 资产即数据** | `art:` 自然语言引用 → 确定性排序选材；扫 `assetKey` 字段**自动出资产清单**、逻辑与美术同源不漂移 |
| **UI 即数据** | 闭集 `UINode` 声明式布局 + 通用解释器；事件=信号名、绑定=resourceId（红线：不滑向图灵完备 UI DSL） |
| **AI 玩家 · 自动质检 / 平衡** | 确定性 + 数据状态 = **完美的无头自对弈环境**：读真实状态(不幻觉)、合法动作天生可枚举、可快进几千局 → 自动 QA + 自动调数值 |
| **平台无关的服务层** | sim 产数据 cue（render-only 组件 / Flag），服务（音频/Steam/存档）**outcome-first 读 cue**、在 hash 外 → 确定性不被平台/IO 污染 |
| **跨模型一致 + 低成本** | 不必绑最贵模型（《21点》用约 1/10 成本小模型已生成）→ 降本 + 一致 |

> **读法**：上表不是"我们做了 10 个功能"，而是"**我们在地基做了一个决定，这 10 件事就成了它的影子**"。这就是设计独特性。

## 4. 横向对比（技术层）

| | 传统引擎 (Unity/Unreal) | 代码生成 (Copilot / 一键生成) | 通用 RAG / 微调 | **ZeroCraft（游戏即数据）** |
|---|---|---|---|---|
| AI 产出 | —（为程序员造） | 自由代码 / 黑盒 | 帮写代码 | **数据（闭集组件+能力）** |
| 确定性 | 非一等不变量 | 无 | 检索常非确定 | **一等不变量（hash/回放）** |
| 可运行下限 | 靠人 | **无**（跑出来才知道） | 靠人 | **构造即可运行** |
| 可复现 | 弱 | 几乎不可能 | 弱 | **逐字节** |
| 接美术/迭代管线 | 强但靠人 | 漂移 | — | **资产即数据·自动对齐** |
| 模型依赖 | — | 必须最强模型 | 微调易幻觉函数名 | **强弱皆可·自适应** |
| 取舍 | 画面强 / LLM 难原生 | 演示炫 / 不可生产 | — | **画面弱 / LLM 最原生** |

**一句话定位**：我们不做更好的 Unreal——我们做**第一台 AI 能原生"对话"的确定性数据引擎**；在"**可创作性 > 画面保真度**"的地方赢。

## 5. 知识组织：派生式分层索引（为什么不是通用 RAG）

让 LLM"懂引擎去生成"，业界默认上"向量库 RAG over 源码 + tree-sitter 抽接口"。对我们**三处不必要、且有害**：
1. **派生而非解析**：引擎已自描述 → 索引 = `buildCapabilityCatalog` **一函数派生**，零漂移；不必 AST/tree-sitter 抽源码。
2. **确定性符号检索**：关键路径命中 `semantic` 标签 + `whenToUse`（确定性）；embedding 只当**可选模糊召回 ranker**——否则破"可复现/弱模型一致"招牌（注：用向量库做检索，与"反对微调幻觉"自相矛盾）。
3. **索引的是数据不是代码**：单元 = **能力卡（组件 schema）+ 样例蓝图（数据）**，服务**数据生成**，非函数签名服务代码生成。
- **分层（粗→细）**：L0 文法骨架(常驻) → L1 能力卡(按需) → L2 样例配方 → L3 陷阱/最佳实践；模型经工具 `searchCapabilities/getCard/getSamples` **按需查**，不全量塞 context。

## 6. 诚实边界（技术取舍，给内行看真东西）
- **画面/实时保真弱于** Unity/Unreal——这是**主动取舍**（换 LLM 原生可创作性 + 确定性）。故首发垂类选**画面最不决定成败**的卡牌/桌游。
- **当前前沿（在攻 / 在排）**：UI-as-data 三套未收敛、manifest 管线未成游戏唯一入口、单消费者能力的防臃肿、AI 玩家通用化、自适应约束环（专利②）落地。**设计独特性不依赖这些完工**——它们是这套设计的**兑现进度**，不是它成立的前提。

## 7. 术语 / 专利映射（备查）
- 范式：**游戏即数据 Game-as-Data**；引擎：**确定性数据解释器**；生成法：**约束式数据合成**。
- **专利①**：自描述目录注入 + 闭集数据产出 + 确定性装配（约束式数据合成）。
- **专利②**：强弱模型方差拟合 + 自适应约束调和（可调和一致性）。
- 拱心石：确定性（hash/快照/lockstep/回放）。
