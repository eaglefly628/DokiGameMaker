# ZeroCraft 视觉评分卡（Visual Scorecard · 验收/出货门）

> 2026-07-06 owner 批（TGS 吸收 A 件·出处 `docs/design/art-pipeline-vision-2026-07.md` §八）。
> 定位：**视觉里程碑验收与出货判定的结构化载体**——替代散文式 MANUAL CHECK。判官=Lead / P3D（3D 线）。
> 挂两处：① P3D 视觉里程碑验收（3D/盒庭线）；② PS 出货内门（Steam 上架前必过）。
> 提醒：这是「LLM 写代码」路线（TGS 原版）的护栏移植——**吸收的是护栏纪律，不是路线**；ZeroCraft 的画面仍全部经数据（组件闭集）产生。

## 一、打分法

- 每维 **0-3 分**：0=缺失/敷衍 · 1=有但粗糙（占位感）· 2=达标（可出货底线）· 3=出色（有记忆点）。
- **premium 线 = 全维 ≥2**（一维不及格即整体不及格——短板决定观感，总分不能补）。
- 判词 token（闭集）：`VISUAL: <总分>/24 · PREMIUM: YES|NO`，逐维给分附一句理由。
- **无证据不给分**：每维打分必须挂证据（截图路径 / 台账条目 / 探针输出），空口自评一律记 0。

## 二、八维（ZeroCraft 裁法）

| 维 | 看什么 | 2 分底线 |
|---|---|---|
| 1. 艺术方向 | 全局有没有一个统一的风格判断（配色/形体语言/氛围一口气） | 三屏截图并排看是同一款游戏；主题令牌/预设一致，不是零件拼盘 |
| 2. 主角面 | 玩家盯着看的主体（主角/核心棋子/炮塔/卡面） | **非纯程序化图元充数**（真贴图/Model3D/精修图元组合）；有辨识度 |
| 3. 世界密度 | 场景是否空旷如测试关（地面/背景/装饰层次） | 主场景 ≥3 个层次（地表+装饰+氛围件），无大片裸色空地 |
| 4. 材质 | 表面是否有质感（PBR 预设/贴图/表面细节） | 主要表面用了材质系统（preset/贴图/surface），非全场单色 flat |
| 5. 渲染管线 | 光照/后处理是否经过设计 | 主光+补光有意图；Post3D/氛围至少一项有设计而非默认值 |
| 6. VFX | 关键动作有没有反馈特效（击中/死亡/得分） | 核心循环的三个关键时刻都有特效反馈，且不喧宾夺主 |
| 7. UI 美术 | HUD/菜单是否与游戏风格一体 | 用主题令牌/艺术字/闭集填充成体系；非默认灰控件裸摆 |
| 8. 性能证据 | 有没有机器证据而非"看起来流畅" | bench/像素断言/帧率数据至少一项在案（引用输出，不引用感觉） |

## 三、证据台账（打分的原料）

- **资产来源台账**：每个「主角面」资产记录一行——`来源(procedural|generated|imported|hybrid) + 产物路径 或 blocker 说明`。主角面选了 procedural 而无 blocker 记录 → 维 2 直接 ≤1。
- **凭证探针**：任何「没 key / 没环境所以跳过」的说法，必须先贴探针输出（缺哪个 env、调用返回什么）——空口 skip 不采信（同 `docs/playbooks/testing.md` 红线）。
- **前后对比**：视觉改造类工单验收附改前/改后截图对（`scripts/shoot-game.mjs` 3D 线）。

## 四、反捷径工艺律（红线）

- **顺序律：先造型 → 再材质 → 再光照 → 最后特效。** 禁止给素坯糊 Glow3D/bloom 冒充质感——特效是最后一道，不是遮羞布。
- **主角面禁纯程序化**（除非台账记录 blocker：如资产线未通、等生成配额）。
- 分数只认证据；「我调过了」不是证据，截图+数据才是。

## 五、什么时候用 & 查不到怎么办

- 用：3D/视觉里程碑验收（P3D 完工回执附自评分 → Lead 复核）；PS 出货前（全维 ≥2 才许上架材料写 premium 词）；美术工坊大批产物入库后的抽检。
- 不用：日常小改（一颗按钮换色）不必全卡——但改动所在维的证据纪律照旧。
- 维度不适配新品类（如纯文字游戏无"世界密度"）→ `docs/workflow/requests.md` 提缺口由 Lead 裁维度豁免，**不得自行跳维**。
