# 复查门手册（三门制 · REQ-QC-三门）

> owner 2026-07-15 拍板：「每步要有其他 session 复查或自检自查——做出来的品质比想象中低。」
> 病根：机器门测的全是「能不能跑」，品质所在的关（美术/品质）恰是纯人门、被跳过；session 自己给自己打分。
> 药方：每关三道门——**机器门（真跑）→ 复查门（另一双眼睛照单核证）→ 人门（owner 签）**。

## 一、三门各管什么

| 门 | 谁执行 | 验什么 | 工具 |
|---|---|---|---|
| 机器门 | 电脑 | 能跑/纪律（parse·测试·审计·三绿） | `game-pipeline.mjs gate` |
| **复查门** | **另一个 session**（复查人≠施工人） | **手册守没守·质量到没到**（对抗性逐条核证） | `checklist` → 核证 → `review` |

> **领工声明铁律（Lead 2026-07-17 回填·game-b S3 复查暴露缺口）**：施工 session 领任何阶段工，第一动作在该游戏工单池落**领工声明**（启动词+代码基线+「碰过的文件」边界栏·样板=game-t T-101）——复查门范围核查以它为对照基准；无声明=复查人只能以提交实录代查并记缺陷。**带设计稿（mockup/dc 稿）的 UI 单，领工声明必须附设计稿渲染目击截图**——只读文字描述就施工=本铁律 FAIL（game-b S3→S5 教训 2026-07-17：坐标 1:1 落了、视觉规格零消费）。
| 人门 | owner/Lead 真人 | 最终裁量（好不好玩/值不值） | `signoff` |

## 二、复查 session 怎么干活（开工三步）

1. `node scripts/game-pipeline.mjs checklist <slug> <SN>` —— 打印该关复查清单（唯一开工命令）。
2. **逐条对抗性核证**：不信施工方的话，自己打开文件/跑命令验。结论必须带 `file:line` 或实数，空口不算。
3. `review <slug> <SN> --verdict PASS|CONCERNS|FAIL --note "逐条结论" --by 复查人` 落账。
   - `PASS`=全条过；`CONCERNS`=有条件过（问题记录在案·可推进）；`FAIL`=打回（该关红灯·修完重跑机器门再来）。

## 三、各关复查覆盖（清单全文在 `game-pipeline.mjs` REVIEW_CHECKLISTS·checklist 命令打印）

- **S2** 能力计划：能力实名核真 / 无虚胖数据 / 例外有裁决 / 美术接入已答。
- **S3** 骨架：纯 JSON 无代码走私 / 与 plan 一致 / 落盘门证据新鲜 / 无死数据。
- **S4** 玩法：测试断言行为非常量（**假信心自查：故意改坏应变红**）/ 循环闭环 / 失败路径 / 确定性。
- **S5** UI：LayoutNode 纪律 / 棘轮绿 / `/check-ui` 四关 / 交互可发现。
- **S7** 品质：**复查形态=评分卡**（`docs/playbooks/visual-scorecard.md` 八维 0-3·由复查人打分·无证据不给分）：
  `scorecard <slug> --scores "艺术方向:N,主角面:N,世界密度:N,材质:N,渲染管线:N,VFX:N,UI美术:N,性能证据:N" --by 复查人 --note 逐维证据`。
  **任一维 0 分=该关红灯；全维≥2 才 premium**——丑必须明明白白写在板上，这就是抬下限的那道门。
- **S8** 终检：证据绑 HEAD 净树 / 并发下仍绿 / 手册缺口回填。
- 豁免：S1（owner 亲提免查）、S6（复核已内嵌美术平台逐行 ☑）。

## 四、红线（防橡皮图章）

- **范围核查=每关复查第一条（owner 2026-07-15 批③）**：施工方领工时须声明改动范围（工单「边界」栏/领工留言）；
  复查人跑 `git diff --stat` 对照——**碰了声明外的文件=FAIL**（偏离手册最终都表现为碰了不该碰的文件·这是硬证据）。
- **复查人≠施工人**：正路=另开 session/子代理只干复查这一件事（effort 档位=high，对抗性验证类=xhigh）。
  确实只有一个 session 时允许自查，但 `--by` 必须如实写（如 `self`），板上可见、验收时打折看待。
- **空 note 不收**（工具已拒）；结论无 file:line/实数 = 无效复查，验收时按未查处理。
- **复查绑内容指纹**：游戏文件一动，复查自动标 ⚠过期须重查（与机器门同一条「绿不是永久绿」纪律）。
- **FAIL 不是终点是打回**：修完 → 重跑该关机器门 → 重新复查。不许绕过复查直接找 owner 签。
- 评分卡维度不适配（如纯文字游戏无「世界密度」）→ `requests.md` 提缺口由 Lead 裁豁免，**不得自行跳维**。

## 五、查不到怎么办

清单条目答不了 / 新关要加复查项 → `docs/workflow/requests.md` 提缺口等裁决（手册对产出负全责·复盘只问手册哪里没接住）。
