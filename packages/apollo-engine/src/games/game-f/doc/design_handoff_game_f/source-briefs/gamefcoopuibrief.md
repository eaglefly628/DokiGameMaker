# Game F「孙刘抗曹」双人合作 · UI 设计简报（给 Claude designer）

> 2026-06-10 · 委托方：策划 PF（用户拍板） · 性质：**设计简报(brief)**，不是实现。
> 配套策划案：`docs/game-design/game-f-coop-sunliu.md`（合作规则/战场/架构）；单机流程：`game-f-flow-spec.md` §〇.5 一图流。
> 红线：① UI 是表现层,**不碰 world/hash/逻辑**；② 游戏内 HUD 走**数据实体词汇**（见 §3,不写 React 进游戏）；③ 沿用 `ui-foundation-brief.md` 的基础库与「青瓷×墨蓝×淡金」基调,**不另立设计语言**。

---

## 0. 一句话需求

为「2 真人(蜀+吴)联军 vs AI 魏」的合作模式设计**两端完全一致**的对局界面：同一战场同一朝向、各自一套按 owner 参数化的操作区、布阵实时互见——让"孙刘联军在同一张桌上排兵"的感觉立起来。

## 1. 设计原则（已拍板,不可推翻）

1. **同视角同 UI**：两端渲染同一个世界、同一个朝向(魏上/蜀左下/吴右下)。"左翼""中缝""桥头"对两人指同一处——**沟通词汇统一是合作 UI 的第一性需求**。不做镜像(镜像属 PvP)。
2. **一份模板,两份实例**：操作区/面板是按 owner 参数化的**同一份数据模板**;不是给 p2 另画一套。
3. **透明白送**：队友的商店/金币/席位本来就在共享世界里——设计上**默认可见**(精简镜像),“偷看队友”不是功能是常态。
4. **唯一端间差异 = 我是谁**：我的区域高亮/可交互,队友的只读(点了无效,给轻反馈)。

## 2. 屏幕分区（1280×720 基准;具体坐标/层级是你的交付物）

```
┌──────────────────────────────────────────────────────────────┐
│ A 队友镜像条(可折叠): 头像·国色 金· Lv· 连胜· 席位缩略· 商店缩略· ✅就绪 │ ← 单机版此条隐藏,布局预留
├──────────────────────────────────────────────────────────────┤
│ B 战场(赤壁): 魏军区(上,梯形窄边)                                │
│    ～～长江(水纹)～ ════桥════  ════桥════ ～～                  │
│    蜀军区(左下) ｜ 吴军区(右下)        C 右侧栏: 团队❤ 阶段/回合   │
│    🧍主公A  🧍主公B(双主角同场)              羁绊面板·⚑标记按钮    │
├──────────────────────────────────────────────────────────────┤
│ D 我的操作区: 金/Lv/连胜/经验 ｜ 备战席9格 ｜ 商店5槽+🔒+刷新+买XP │
│    [🎁赠予] [⚔开战(等待队友…/双✅)]                              │
└──────────────────────────────────────────────────────────────┘
```

- **D 区 = 单机操作区原样**(商店 5 槽/HUD 数字/ready 键已上线,F-14/F-15/F-049~053)——合作只是在它之上加 A/C 的合作件。**给单机做视觉精修时,A 条的高度先留出来。**
- 战场含**梯形缺角、长江水带、双桥**——这是美术叙事重点(赤壁),水纹/桥面/两岸营寨用 DCSS 地块语言(`dungeon/floor/*` 冷暖分岸)。

## 3. 可用的实现词汇（设计必须落在这套词汇内,这是硬约束）

| 词汇 | 用途 | 现状 |
|---|---|---|
| `Sprite/Text/Shape/Color` 实体 | 面板/文字/色块/图标 | ✅ 在用 |
| `Gauge` | 任何"比例条"(血/蓝/经验/倒计时) | ✅ 在用 |
| `text-binding`(REQ-F-043) | 资源数字实时投影(金币/等级/回合) | ✅ 在用 |
| `clickable` + 命令路由 | 按钮/槽位点击(按 owner) | ✅ 在用(ready/商店) |
| 拖拽(REQ-F-045) | 摆子/(将来)赠予拖放 | ✅ 在用 |
| `Hierarchy` + 级联 | 跟随单位的挂件(条/名牌/星角标) | ✅ 在用 |
| 壳层 DOM(shell) | 对局**外**的横幅/结算页/房间页 | ✅ 在用(主题见 ui-foundation-brief) |

> 没有的词汇(如粒子/遮罩动效)→ 在交付物里**标注为新需求建议**,由策划入池评审,**不要假设它存在**。

## 4. 需要你设计的组件清单（合作专属增量）

| # | 组件 | 状态要求 |
|---|---|---|
| 1 | **队友镜像条**(A 区) | 折叠态(一行)/展开态(席+商店全貌);就绪✅/未就绪;断线置灰(预留) |
| 2 | **双 ready 开战键** | 我未按/我已按等待队友(脉冲)/双✅起战(与现单机 ready 键同体演化) |

| 5 | **所有权语言** | 我=描边高亮可拖;队友=国色徽记只读(点击给"是队友的"轻反馈);敌=现有红蓝语义并入三国色(蜀红/吴绿/魏蓝) |
| 6 | **联盟羁绊点亮**(火烧赤壁) | 羁绊面板里跨玩家条目的"半亮(我半边已凑)/全亮(双方凑齐)"两段式——这是合作的招牌时刻,给足仪式感 |

| 8 | **赤壁战场皮**(B 区) | 梯形岸线/水带/双桥/两岸营寨;法球与招降标记落在中线与桥头的可读性 |

## 5. 交付格式（对齐既有 designer 流程）

1. **布局规格表**：每组件的区域坐标(1280×720)、层级 zOrder、折叠/展开尺寸;
2. **状态机图**：组件 2/3/6 的全部交互态(含不可用/等待/失败反馈);
3. **资产 key 清单**：需要的贴图/图标按 `f.ui.*` 命名(走 R9 资产流程,先占位后真图);
4. **数据实体草稿**(能写多少写多少)：按 §3 词汇把组件拆成实体+组件字段——最弱 LLM 能照抄落地的程度;
5. 单机即时项单列：**A 条占位高度** + 组件 5 的色语言(单机三方 C1 也用)。

## 6. 别做的事

- 别给 p1/p2 设计两套不同布局(违反原则 2);
- 别设计需要"每端各自世界状态"的元素(违反 lockstep——一切 UI 状态要么是共享 SIM 数据,要么是纯本地表现);
- 别推翻单机已上线的 HUD/商店面板形态——合作件是**加层**,不是重做。
